# Подробное описание проекта «Игра “Угадай число”»

## 1. Карточка проекта

| Поле | Значение |
|---|---|
| Название | Number Guessing Game / «Игра “Угадай число”» |
| Тип | Одноэкранное учебное мобильное приложение |
| Назначение | Угадать случайное целое число от 1 до 100 по подсказкам `too low` и `too high` |
| Платформа | React Native под управлением Expo |
| Версии проекта | Expo `~54.0.36`, React `19.1.0`, React Native `0.81.5` |
| Минимальная версия Node.js | `>=20.19.4` |
| Главный экран | `App.js` |
| Предметная логика | `src/number-guessing.js` |
| Автоматические проверки | `__tests__/App.test.js`, `__tests__/number-guessing.test.js` |
| Хранение данных | Только оперативное состояние React; постоянного хранилища нет |
| Язык интерфейса | Английский |
| Учебный уровень | Начальный React Native после знакомства с JavaScript-функциями и условиями |

Приложение реализует один законченный игровой цикл: создание секрета, ввод догадки, проверка, подсказка, подсчёт допустимых попыток, сообщение об успехе и начало нового раунда после нажатия `OK`.

## 2. Условие задания и точный перевод

**Оригинальная формулировка со скриншота:**

> Number Guessing Game app
>
> Create Number Guessing game where user have to guess the random secret
> number between 1-100 (see the screenshots).
>
> When game starts, the following message is shown and a user can type a guess.
>
> When a user press 'Make Guess'- button, the answer is compared to secret
> number. If the guess was smaller or bigger than secret number, the following
> messages are shown:
>
> When a user make correct guess, the game ends and the following message is shown:
>
> Hint: Random number between 1-100, `Math.floor(Math.random() * 100) + 1`

**Точный перевод:**

> Приложение «Угадай число».
>
> Создайте игру, в которой пользователь должен угадать случайное секретное
> число от 1 до 100 (см. скриншоты). После начала игры отображается подсказка,
> и пользователь может ввести предполагаемое число. После нажатия кнопки
> Make Guess ответ сравнивается с секретным числом. Если введённое число
> меньше или больше секретного, показывается соответствующее сообщение.
> После правильного ответа игра завершается и показывается итоговое сообщение.
>
> Подсказка для генерации числа от 1 до 100:
> `Math.floor(Math.random() * 100) + 1`.

Уточнения, реализованные в текущей версии:

- границы диапазона включены: допустимы `1` и `100`;
- принимаются только строки, представляющие целые числа из диапазона;
- пустой ввод, дробная запись, знаки, экспоненциальная и шестнадцатеричная запись, текст и значения вне диапазона не считаются попыткой;
- после правильной догадки открывается нативный `Alert`;
- новый секрет и сброс интерфейса происходят только после кнопки `OK` в `Alert`.

## 3. Результаты обучения

После разбора и воспроизведения проекта ученица сможет:

1. Объяснить назначение `useState` и назвать все пять состояний приложения.
2. Создать управляемый `TextInput`, связав `value={guessInput}` и `onChangeText={setGuessInput}`.
3. Отличить строку пользовательского ввода от проверенного числа.
4. Реализовать ранний выход из обработчика, чтобы неверный ввод не менял счётчик.
5. Вывести целое число в диапазоне `[1, 100]` формулой `Math.floor(randomValue * 100) + 1`.
6. Разделить интерфейс и чистую предметную логику.
7. Передать callback в событие, не вызывая его преждевременно.
8. Объяснить, почему для текста правильной попытки нужен `nextCount`, а не старое значение `attemptCount`.
9. Написать unit-тесты чистых функций и UI-тест управляемого поля, кнопки, `Alert` и сброса раунда.
10. Провести ручную приёмку на Android или iOS и аргументированно защитить решение на русском и английском языках.

## 4. Функциональные критерии готовности

| № | Критерий | Фактическая реализация | Как проверить |
|---:|---|---|---|
| 1 | Секрет лежит в `[1, 100]` | `createSecretNumber` применяет `Math.floor(randomValue * 100) + 1` | Unit-тест границ `0 → 1`, `0.999999 → 100` |
| 2 | Секрет не меняется при обычном рендере | `useState(() => createSecretNumber(Math.random()))` | UI-тест проверяет один вызов `Math.random` до нового раунда |
| 3 | Есть начальная инструкция | `Guess a number between 1-100` | `testID="hint-message"` |
| 4 | Ввод управляемый | `value={guessInput}`, `onChangeText={setGuessInput}` | Ввести текст и затем проверить очистку после `OK` |
| 5 | Допустимы только целые `1–100` | `parseGuess` сначала проверяет `/^\d+$/`, затем диапазон | Набор положительных и отрицательных unit-тестов |
| 6 | Ошибка не считается попыткой | Ранний `return` предшествует вычислению `nextCount` | После `0x10` остаётся `Attempts: 0` |
| 7 | Низкая догадка получает подсказку | Статус `low`, сообщение `Your guess N is too low` | При секрете 75 ввести 50 |
| 8 | Высокая догадка получает подсказку | Статус `high`, сообщение `Your guess N is too high` | При секрете 75 ввести 90 |
| 9 | Допустимые догадки считаются | `setAttemptCount(nextCount)` | 50, 90, 75 дают итог 3 в тестовом раунде |
| 10 | Успех показан через `Alert` | Заголовок `Correct!`, текст `You guessed the number in N guesses` | UI-тест проверяет точные аргументы `Alert.alert` |
| 11 | Новый раунд начинается по `OK` | `onPress: startNewRound` | Вызвать callback и проверить новый секрет и сброс всех видимых значений |
| 12 | Элементы имеют доступные текст и props | У поля есть `accessibilityLabel="Guess input"`; динамические тексты видимы, а `accessibilityLiveRegion="polite"` помогает TalkBack на Android | Инспекция props, UI-тесты и отдельная ручная проверка TalkBack/VoiceOver |

Проект считается принятым, если автоматические тесты проходят, приложение запускается, а ручная проверка подтверждает критерии 3–12.

`accessibilityLiveRegion` документирован как Android-prop. Поэтому
автоматическое объявление динамического текста проверяется с TalkBack, а на
iOS поведение VoiceOver подтверждается отдельно и не выводится из одного этого
prop.

## 6. Архитектура и ответственности

Приложение разделено на два слоя.

### Слой интерфейса — `App.js`

Он отвечает за:

- создание и обновление React state;
- отображение карточки игры и правил;
- приём строки из `TextInput`;
- запуск обработки по `MAKE GUESS`;
- вывод подсказки, счётчика и ошибки;
- показ `Alert` после правильной догадки;
- сброс состояния по `OK`;
- визуальные стили и свойства доступности.

### Слой предметной логики — `src/number-guessing.js`

Он не зависит от React Native и содержит четыре функции:

- `createSecretNumber(randomValue)` преобразует значение из `[0, 1)` в целое `[1, 100]`;
- `parseGuess(text)` валидирует строку и возвращает объект успеха или ошибки;
- `compareGuess(secret, guess)` возвращает литерал `low`, `high` или `correct`;
- `buildGuessMessage(status, guess)` строит подсказку для неверной допустимой догадки.

Такое разделение делает вычисления детерминированными и позволяет проверять их без рендера мобильного интерфейса. `App.js` координирует функции, но не дублирует их правила.

## 7. Модель состояния

| State | Начальное значение | Тип во время работы | Кто изменяет | Назначение |
|---|---|---|---|---|
| `secretNumber` | `createSecretNumber(Math.random())` через ленивый инициализатор | `number` | `setSecretNumber` в `startNewRound` | Секрет текущего раунда |
| `guessInput` | `''` | `string` | `setGuessInput` из `onChangeText` и `startNewRound` | Точное содержимое управляемого поля |
| `message` | `'Guess a number between 1-100'` | `string` | `setMessage` после неверной допустимой догадки и при сбросе | Начальная инструкция или подсказка `low/high` |
| `attemptCount` | `0` | `number` | `setAttemptCount` после допустимого ввода и при сбросе | Число только допустимых попыток |
| `errorMessage` | `''` | `string` | `setErrorMessage` после проверки и при сбросе | Сообщение о недопустимом вводе |

Инварианты состояния:

- `secretNumber` всегда целое от 1 до 100;
- `guessInput` остаётся строкой даже тогда, когда содержит цифры;
- `attemptCount` — неотрицательное целое и не увеличивается при `parsed.ok === false`;
- после допустимой догадки `errorMessage === ''`;
- после `startNewRound` поле, ошибка и счётчик сброшены, подсказка начальная, секрет новый;
- состояние не сохраняется после закрытия или полного перезапуска приложения.

## 8. Поток данных и событий

```text
Пользователь печатает
        │
        ▼
onChangeText → setGuessInput → guessInput
        │
        ▼
нажатие MAKE GUESS → handleGuess
        │
        ▼
parseGuess(guessInput)
   ├── ошибка → setErrorMessage(parsed.error) → return
   │             attemptCount не меняется
   └── успех → nextCount = attemptCount + 1
               compareGuess(secretNumber, parsed.value)
               setAttemptCount(nextCount)
               setErrorMessage('')
                  ├── low/high → buildGuessMessage → setMessage
                  └── correct → Alert.alert
                                      │
                                      ▼
                                OK → startNewRound
                                      ├── новый secretNumber
                                      ├── guessInput = ''
                                      ├── message = начальная строка
                                      ├── attemptCount = 0
                                      └── errorMessage = ''
```

Setter-функции вызывают повторный рендер. Компоненты получают обновлённые значения через JSX. `TextInput` не хранит отдельное «скрытое» значение: источником истины служит `guessInput`.

## 9. Алгоритмы

### 9.1. Создание секрета

```js
Math.floor(randomValue * 100) + 1
```

Для `randomValue ∈ [0, 1)` произведение лежит в `[0, 100)`, `Math.floor` даёт одно из целых `0–99`, а прибавление единицы переносит результат в `1–100`.

### 9.2. Проверка ввода

`parseGuess` выполняет последовательность:

1. `text.trim()` удаляет пробелы по краям.
2. Регулярное выражение `/^\d+$/` требует одну или более десятичных цифр и всю строку целиком.
3. `Number(normalized)` преобразует уже проверенную запись.
4. Условие `value < 1 || value > 100` отклоняет выход за диапазон.
5. Успех имеет форму `{ ok: true, value }`, ошибка — `{ ok: false, error: 'Enter a whole number from 1 to 100.' }`.

Запись `'075'` принимается и превращается в `75`. Записи `'+5'`, `'-5'`, `'7.5'`, `'1e2'`, `'0x10'` и `'1,0'` отклоняются, хотя некоторые из них JavaScript мог бы преобразовать через `Number`.

### 9.3. Сравнение

- `guess < secret` → `low`;
- `guess > secret` → `high`;
- иначе → `correct`.

Статус описывает **догадку относительно секрета**: `low` означает «догадка слишком мала», а `high` — «догадка слишком велика».

### 9.4. Подсказка и счётчик

Для `low/high` вызывается `buildGuessMessage(status, parsed.value)`, например `Your guess 50 is too low`. Значение `nextCount = attemptCount + 1` вычисляется до обновления state, поэтому правильная текущая попытка уже входит в текст `Alert`.

### 9.5. Новый раунд

В массив кнопок `Alert.alert` передаётся `{ text: 'OK', onPress: startNewRound }`. Это ссылка на функцию. Запись `onPress: startNewRound()` была бы ошибкой: сброс произошёл бы при создании диалога, не после действия пользователя.

## 10. Валидация и обработка ошибок

Пользователь видит одну точную строку ошибки:

```text
Enter a whole number from 1 to 100.
```

Она возникает для:

- пустой строки и строки только из пробелов;
- дробей (`7.5`, `1.0`, `1,0`);
- значений ниже и выше диапазона (`0`, `101`);
- знаковых записей (`+5`, `-5`);
- альтернативных числовых форматов (`0x10`, `1e2`);
- произвольного текста (`hello`).

Обработка безопасна для игрового состояния: устанавливается только `errorMessage`, затем `handleGuess` завершается ранним `return`. Секрет, подсказка и счётчик не изменяются. Следующая допустимая догадка очищает ошибку через `setErrorMessage('')`.

Цифровая клавиатура `keyboardType="numeric"` облегчает ввод, но не является проверкой: набор доступных символов зависит от платформы, а значение всё равно поступает строкой. Окончательное правило реализует `parseGuess`.

## 11. Запуск с нуля: Windows + Android и macOS + iOS

Проект уже создан, поэтому команду `create-expo-app` выполнять не нужно. Все команды запускаются из корня `04-number-guessing-game`.

### 11.1. Общие требования

1. Установить Node.js версии не ниже `20.19.4` и npm.
2. Проверить версии:

   ```text
   node --version
   npm --version
   ```

3. Установить зафиксированные зависимости:

   ```text
   npm ci
   ```

4. Убедиться, что проект использует Expo SDK 54: в `package.json` зависимость `expo` равна `~54.0.36`.

`npm ci` предпочтительнее `npm install` для первого воспроизводимого запуска, потому что использует `package-lock.json` и не пересчитывает набор версий.

### 11.2. Windows и Android

1. Установить Android Studio, Android SDK, Platform Tools и создать Android Virtual Device либо подготовить физическое Android-устройство с Expo Go, совместимым с SDK 54.
2. Запустить эмулятор и дождаться полной загрузки Android. Для физического устройства компьютер и телефон должны видеть один сервер разработки; при необходимости разрешить сетевой доступ Metro в брандмауэре.
3. В корне проекта выполнить:

   ```text
   npm ci
   npx expo start
   ```

4. Для эмулятора нажать `a` в терминале Metro. Эквивалентная команда проекта: `npm run android`.
5. Для физического устройства открыть Expo Go и отсканировать QR-код Metro.
6. Если Metro использует устаревший кеш, остановить его сочетанием `Ctrl+C` и выполнить `npx expo start --clear`.

Официальная справка Expo по Android Emulator: <https://docs.expo.dev/workflow/android-studio-emulator/>.

### 11.3. macOS и iOS

1. Установить Node.js `>=20.19.4`, Xcode из Mac App Store и доступный iOS Simulator. Один раз открыть Xcode, принять лицензию и завершить установку компонентов.
2. В корне проекта выполнить:

   ```text
   npm ci
   npx expo start
   ```

3. Нажать `i` в терминале Metro. Эквивалентная команда проекта: `npm run ios`.
4. Если симулятор не открылся автоматически, сначала запустить приложение Simulator, выбрать устройство, затем повторить `i`.
5. На физическом iPhone можно открыть проект через совместимую с SDK 54 версию Expo Go и QR-код. iOS Simulator доступен только на macOS.

Официальная справка Expo по iOS Simulator: <https://docs.expo.dev/workflow/ios-simulator/>. Expo описывает Expo Go как подходящую учебную среду; для production-проектов с собственными нативными модулями требуется development build, но текущему проекту такие модули не нужны.

## 12. Тестирование и приёмка

### 12.1. Автоматические команды

После `npm ci` выполнить:

```text
npm test -- --runInBand
npx expo-doctor
```

При необходимости проверить возможность построения статического bundle:

```text
npx expo export --platform android
```

### 12.2. Что проверяют unit-тесты

`__tests__/number-guessing.test.js` подтверждает:

- обе границы генератора секрета;
- пробелы вокруг корректного числа и допустимость `'075'`;
- отклонение 11 классов ошибочных строк;
- статусы `low`, `high`, `correct`;
- точные сообщения `Your guess 50 is too low` и `Your guess 90 is too high`.

### 12.3. Что проверяет UI-тест

В `__tests__/App.test.js` `Math.random` детерминирован: `0.74` создаёт 75, после `OK` `0.24` создаёт 25. Тест проверяет:

1. `0x10` показывает ошибку и не увеличивает `Attempts: 0`.
2. `50` даёт `Your guess 50 is too low`, счётчик 1.
3. `90` даёт `Your guess 90 is too high`, счётчик 2.
4. `75` вызывает `Correct!` и `You guessed the number in 3 guesses`.
5. Callback кнопки `OK` создаёт новый секрет и сбрасывает поле, подсказку и счётчик.
6. Во втором раунде `30` слишком велико для 25, а `25` завершает игру за две попытки.

### 12.4. Ручная приёмка

При обычном запуске секрет неизвестен, поэтому не следует ожидать, что фиксированная последовательность `50 → 90 → 75` всегда сработает. Ручной сценарий:

1. Убедиться, что видны `Number Guessing Game`, начальная подсказка и `Attempts: 0`.
2. По очереди проверить пустую строку, `7.5`, `0`, `101` и текст: ошибка точная, счётчик не меняется.
3. Ввести целое `1–100`: счётчик увеличивается ровно на один.
4. По `too low` выбирать большее число, по `too high` — меньшее, пока не появится `Alert`.
5. Сверить количество попыток в `Alert` с видимым прогрессом.
6. Нажать `OK`: поле пустое, ошибка исчезла, подсказка начальная, попыток 0.
7. Сделать допустимую догадку в новом раунде и убедиться, что игра продолжает работать.

- диапазон фиксирован значениями 1 и 100;
- язык интерфейса фиксирован английским;
- секрет не отображается и не имеет режима отладки в UI;
- нет отдельной кнопки досрочного нового раунда;
- нет истории догадок, таймера, уровней сложности и лучшего результата;
- нет сохранения между перезапусками;
- нет серверной части, учётной записи, аналитики и сетевого обмена;
- `buildGuessMessage` предназначена для `low/high`; для `correct` она не вызывается;
- регулярное выражение принимает ведущие нули (`'075' → 75`), что закреплено тестом;
- `keyboardType="numeric"` не гарантирует одинаковую раскладку на всех устройствах;
- портретная ориентация задана в `app.json`; отдельные макеты для landscape не предусмотрены;
- `Alert` имеет платформенно-зависимое нативное оформление;
- приложение учебное и запускается в Expo Go; production-сборка и публикация не входят в объём проекта.

Эти пункты описывают границы решения, а не дефекты обязательной версии.

## 14. Защита проекта на русском и английском

### 14.1. Краткое выступление на русском

«Это одноэкранная игра React Native на Expo. В начале раунда ленивый инициализатор создаёт целое секретное число от 1 до 100. Поле ввода управляется состоянием `guessInput`. После нажатия `MAKE GUESS` функция `parseGuess` проверяет строку. Ошибка вызывает ранний выход, поэтому счётчик не увеличивается. Допустимое число сравнивается с `secretNumber`: пользователь получает подсказку `too low` или `too high`, а правильный ответ открывает `Alert`. В тексте успеха используется `nextCount`, уже включающий текущую попытку. Только кнопка `OK` вызывает `startNewRound`, создаёт новый секрет и сбрасывает интерфейс. Чистая логика вынесена в отдельный модуль и покрыта unit-тестами, а полный пользовательский поток — UI-тестом».

### 14.2. Short defense in English

“This is a single-screen number guessing game built with React Native and Expo. A lazy state initializer creates one secret whole number for the current round. The text input is controlled by `guessInput`. When the user presses `MAKE GUESS`, `parseGuess` validates the string. Invalid input causes an early return, so it does not increase `attemptCount`. A valid number is compared with `secretNumber` and produces a low or high hint. A correct guess opens an alert whose total includes the current attempt. Pressing `OK` calls `startNewRound`, creates a new secret, and resets the visible state. Pure game functions have unit tests, while the UI test covers validation, hints, counting, the alert, and a second round.”
