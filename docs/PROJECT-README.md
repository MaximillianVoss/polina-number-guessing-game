## 1. Оригинальное требование и перевод

Формулировка со скриншота:

> Number Guessing Game app
>
> Create Number Guessing game where user have to guess the random secret
> number between 1-100 (see the screenshots).
>
> When game starts, the following message is shown and a user can type a guess.
> When a user press 'Make Guess'- button, the answer is compared to secret
> number. If the guess was smaller or bigger than secret number, the following
> messages are shown. When a user make correct guess, the game ends and the
> following message is shown.
>
> Hint: Random number between 1-100, `Math.floor(Math.random() * 100) + 1`

Точный перевод: создайте игру, в которой пользователь угадывает случайное
секретное число от 1 до 100. После каждого нажатия Make Guess приложение
сравнивает ответ с секретом и сообщает, меньше он или больше. Правильный ответ
завершает текущий раунд и выводит итоговое сообщение.

Пустой ввод, дробное число и значения вне диапазона не считаются попыткой. Правильный ответ показывается через `Alert`, а новый секрет создаётся после кнопки `OK`.

## 2. Реализованные критерии

- секрет — целое число в диапазоне `[1, 100]`;
- начальная подсказка `Guess a number between 1-100`;
- поле `Guess input` с placeholder и цифровой клавиатурой;
- кнопка `MAKE GUESS`, видимые `Hint message`, `Attempt count` и `Error message`;
- `50` при секрете 75 даёт `Your guess 50 is too low`;
- `90` при секрете 75 даёт `Your guess 90 is too high`;
- правильный ответ показывает `You guessed the number in N guesses`;
- `''`, `7.5`, `0`, `101` и текст не увеличивают счётчик;
- `OK` очищает поле, подсказку, ошибку и счётчик, затем создаёт новый секрет.

## 6. Состояние, события и поток данных

`secretNumber` хранит текущий секрет. `guessInput` хранит текст поля. `message` управляет подсказкой, `attemptCount` — числом допустимых попыток, `errorMessage` — ошибкой проверки.

Поток: ввод → `MAKE GUESS` → `parseGuess` → при ошибке ранний выход без счётчика → при успехе `compareGuess` → счётчик увеличивается → для `low/high` меняется подсказка → для `correct` открывается `Alert` → только `OK` вызывает `startNewRound` и сбрасывает state.

## 7. Разбор App.js и чистой логики

В `App.js` выражение `useState(() => createSecretNumber(Math.random()))` является ленивым инициализатором: React вызывает функцию при создании state, а не при каждом рендере. `handleGuess` сначала проверяет строку, затем вычисляет `nextCount`, чтобы Alert получил точное число с учётом текущей попытки. `startNewRound` передан в `Alert` как callback, а не вызван заранее.

В `src/number-guessing.js`:

- `createSecretNumber(randomValue)` реализует `floor(randomValue * 100) + 1`;
- `parseGuess` принимает только целое от 1 до 100;
- `compareGuess` возвращает `low`, `high` или `correct`;
- `buildGuessMessage` создаёт английскую подсказку для неверного допустимого числа.

`Math.random` и нативный `Alert.alert` подменяются только в UI-тесте, чтобы два последовательных раунда и диалог были детерминированными; предметная логика тестируется напрямую.

## 8. React и React Native понятия

- **useState** хранит данные раунда и вызывает рендер после setter;
- **lazy initializer** вычисляет начальное значение только при создании state;
- **controlled TextInput** получает `value` из state и отправляет изменения через `onChangeText`;
- **event handler** запускается после нажатия `MAKE GUESS`;
- **early return** завершает обработчик до увеличения попыток при ошибке;
- **Alert** — нативный диалог, кнопке которого передан callback нового раунда;
- **чистая функция** для одинакового ввода возвращает одинаковый результат и не меняет state;
- **accessibilityLabel** даёт элементу явное назначение для доступности и тестов.

## 10. Ручной приёмочный чек-лист

Последовательность 50, 90, 75 при секрете 75 является детерминированным автоматическим тестом, а не инструкцией для обычного запуска. При ручной проверке секрет случайный, поэтому следующий ввод выбирают по фактической подсказке:

1. Начальный текст — `Guess a number between 1-100`, попыток 0.
2. Пустая строка, `7.5`, `0`, `101`, `0x10` и `1e2` по очереди показывают ошибку; счётчик остаётся 0.
3. Ввести любое целое от 1 до 100, например 50: допустимый ввод увеличивает счётчик ровно на один.
4. Если подсказка говорит `too low`, выбрать большее число; если `too high` — меньшее. Продолжать сужать диапазон по отображаемым подсказкам.
5. При совпадении открывается Alert с фактическим числом допустимых попыток.
6. До нажатия `OK` результат можно прочитать; после `OK` поле пусто, подсказка начальная, попыток 0.
7. Повторить один ввод в новом раунде и убедиться, что подсказка относится к заново созданному секрету; полный перезапуск также начинает свежий раунд.

## 11. Диагностика типичных ошибок

- **Node ниже 20.19.4:** обновите системный Node.js и перезапустите терминал и VS Code; затем повторите обе команды проверки из раздела 3.
- **adb не видит AVD:** запустите `pixel_7_-_api_35_0`, дождитесь загрузки и проверьте `adb devices`.
- **Порт Metro уже занят:** остановите старый сервер или используйте предложенный свободный порт.
- **Кеш Metro устарел:** запустите `npx expo start --clear`.
- **Expo Go не поддерживает SDK 54:** обновите приложение Expo Go.
- **После `a` приложение не открылось:** проверьте AVD/adb, Metro и повторите команду после полной загрузки устройства.

Типичные ошибки кода: `Math.floor(random * 100)` создаёт диапазон 0–99; `Number('')` даёт 0 без отдельной проверки; счётчик нельзя увеличивать до валидации; ветви `guess < secret` и `guess > secret` легко перепутать; `onPress: startNewRound()` вызовет сброс сразу, поэтому передаётся `onPress: startNewRound`.

## 12. Вопросы преподавателя

1. Почему секрет создаётся ленивым инициализатором?
2. Как формула гарантирует диапазон от 1 до 100?
3. Почему `7.5` не считается попыткой?
4. Зачем вычислять `nextCount` до Alert?
5. Чем отличаются статусы `low` и `high`?
6. Почему в `Alert` передаётся функция `startNewRound`, а не результат её вызова?
7. Что сохраняется после полного перезапуска?

## 13. Краткие ответы

1. Чтобы случайное число не менялось из-за обычного повторного рендера.
2. `random * 100` лежит от 0 до почти 100, `floor` даёт 0–99, прибавление 1 даёт 1–100.
3. `parseGuess` принимает только строку из цифр и диапазон `1–100`, поэтому `7.5` отклоняется; ранний выход происходит до setter счётчика.
4. Текущий state ещё содержит старое значение; `nextCount` уже включает правильную попытку.
5. `low` означает, что догадка меньше секрета; `high` — больше секрета.
6. Callback должен выполниться после нажатия `OK`, а не во время создания диалога.
7. Ничего: постоянного хранилища нет, создаётся новый раунд.

## 14. Английские формулировки для защиты

- `The secret is created once for the round.`
- `The random formula maps values to the inclusive range from one to one hundred.`
- `Only a valid whole-number guess increases the attempt count.`
- `A low guess and a high guess produce different hint messages.`
- `The alert includes the current correct guess in the total count.`
- `Pressing OK calls the reset function and creates a new round.`
- `The game state is kept in memory and is not persisted.`
