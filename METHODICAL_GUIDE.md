# Методическое руководство к проекту «Игра “Угадай число”»

## 1. Аудитория и пререквизиты

Руководство рассчитано на индивидуальное 90-минутное занятие с ученицей начального уровня, которая уже видела основы JavaScript и впервые или повторно закрепляет управление состоянием в React Native.

До занятия ученица должна уметь:

- объявлять `const` и функции;
- различать строку, число, объект и логическое значение;
- читать `if`, `return` и шаблонную строку;
- понимать операции `<`, `>`, `+`;
- запускать команду в терминале из открытой папки проекта;
- в общих чертах читать JSX.

Желательно, но не обязательно, знать массивы, регулярные выражения и Jest. Эти темы объясняются на примерах проекта.

Формат занятия предполагает, что готовая версия уже доступна. Ученица не перепечатывает весь проект механически: сначала формулирует правила, затем восстанавливает ключевые фрагменты, прогнозирует результат и подтверждает его тестами.

## 2. Измеримые цели занятия

К концу 90 минут ученица должна без подсказки преподавателя:

1. Назвать назначение `secretNumber`, `guessInput`, `message`, `attemptCount`, `errorMessage` — не менее 5 из 5.
2. Объяснить диапазон формулы `Math.floor(randomValue * 100) + 1` на обоих граничных примерах.
3. Предсказать результат `parseGuess` минимум для 6 из 7 предложенных строк.
4. Восстановить порядок действий `handleGuess`: разбор → ранний выход или сравнение → счётчик → подсказка/`Alert`.
5. Объяснить, почему неверный ввод не увеличивает `attemptCount`.
6. Объяснить пару `value` / `onChangeText` у управляемого `TextInput`.
7. Различить React Native-компонент и API на примерах `Text`, `Alert`, `useState`, `StyleSheet`.
8. Прочитать один unit-тест и один фрагмент UI-теста, указав Arrange, Act и Assert.
9. Провести ручной игровой раунд по фактическим подсказкам.
10. За 60–90 секунд защитить архитектуру по-русски и произнести не менее пяти корректных технических фраз по-английски.

Критерий достижения занятия: не менее 7 баллов из 10 по рубрике раздела 13, при этом обязательны корректная валидация и понимание счётчика.

## 3. Подготовка преподавателя

До встречи преподаватель выполняет следующий чек-лист:

1. Проверяет `node --version`: версия не ниже `20.19.4`.
2. Из корня проекта выполняет `npm ci`.
3. Запускает `npm test -- --runInBand` и убеждается, что оба test suite проходят.
4. Проверяет запуск через `npx expo start` на доступном Android-устройстве/эмуляторе либо iOS Simulator на macOS.
5. Открывает рядом файлы `App.js`, `src/number-guessing.js`, оба файла из `__tests__` и этот документ.
6. Готовит экран или доску для схемы потока данных.

Если окружение не запускается, преподаватель не тратит основную часть урока на установку: демонстрирует уже полученный результат тестов и проводит трассировку кода. Настройку среды завершает после учебного блока по диагностике раздела 11.

- лист/доска для пяти строк state и двух ветвей `parseGuess`.

Минимальная запись на доске:

```text
input string → parseGuess
  invalid → error + return
  valid → count + compare
             low/high → hint
             correct → Alert → OK → reset
```

Карточки для быстрой сортировки: `View`, `Text`, `TextInput`, `Button`, `StatusBar` относятся к отображаемым компонентам; `Alert`, `useState`, `StyleSheet` и `Math.random` — API/функции, а не JSX-контролы приложения.

## 5. Входная диагностика

Диагностика занимает 7 минут и не оценивается в итоговые 10 баллов. Вопросы задаются без открытия исходника.

| Вопрос | Ожидаемый ответ | Если ответа нет |
|---|---|---|
| Что вернёт `' 75 '.trim()`? | Строку `'75'` | Коротко показать удаление пробелов только по краям |
| Чем `'75'` отличается от `75`? | Первое — строка, второе — число | Связать со значением `TextInput` |
| Что делает ранний `return`? | Немедленно завершает текущую функцию | Нарисовать перечёркнутые последующие шаги |

| Что означает `value={state}` у поля? | Значение поля приходит из state | Ввести термин «управляемое поле» после ответа |
| Вызывается ли `onPress={handleGuess}` во время рендера? | Нет, ссылка выполняется при нажатии | Сравнить с ошибочной записью `handleGuess()` |
| Что должен проверять тест? | Наблюдаемый результат для заданного входа | Дать структуру Arrange–Act–Assert |

Интерпретация:

- 6–7 ответов: можно быстрее пройти основы и увеличить самостоятельную практику;
- 3–5 ответов: использовать основной тайминг без изменений;
- 0–2 ответа: сократить разбор регулярного выражения, но обязательно сохранить блоки state, раннего выхода и счётчика.

## 7. Пошаговое программирование

Этот раздел задаёт порядок, в котором удобно воспроизводить решение. На занятии после каждого шага сначала формулируется ожидаемое поведение, затем пишется минимальный код и запускается соответствующая проверка.

### Шаг 1. Зафиксировать контракт чистых функций

Нужны четыре операции:

```js
createSecretNumber(randomValue)
parseGuess(text)
compareGuess(secret, guess)
buildGuessMessage(status, guess)
```

Ученица записывает по одному примеру входа/выхода до реализации: `createSecretNumber(0) === 1`, `parseGuess(' 75 ')` успешно возвращает 75, `compareGuess(75, 50) === 'low'`.

### Шаг 2. Реализовать диапазон секрета

```js
export function createSecretNumber(randomValue) {
  return Math.floor(randomValue * 100) + 1;
}
```

Сразу проверить нижнюю и верхнюю границу unit-тестом. Важно не писать `Math.floor(randomValue * 100)`, потому что это даст 0–99.

### Шаг 3. Реализовать строгий разбор строки

```js
export function parseGuess(text) {
  const normalized = text.trim();
  if (!/^\d+$/.test(normalized)) {
    return { ok: false, error: 'Enter a whole number from 1 to 100.' };
  }
  const value = Number(normalized);
  if (value < 1 || value > 100) {
    return { ok: false, error: 'Enter a whole number from 1 to 100.' };
  }
  return { ok: true, value };
}
```

Сначала проверяется форма записи, потом диапазон. Это намеренно запрещает `1e2`, `0x10`, `+5` и `1.0`.

### Шаг 4. Реализовать сравнение и подсказку

```js
export function compareGuess(secret, guess) {
  if (guess < secret) return 'low';
  if (guess > secret) return 'high';
  return 'correct';
}

export function buildGuessMessage(status, guess) {
  return `Your guess ${guess} is too ${status}`;
}
```

Ученица проговаривает, что `low/high` относятся к `guess`, а не к секрету.

### Шаг 5. Создать state экрана

Создать `App.js` и подключить ровно те зависимости, которые использует
готовый экран:

```js
import { StatusBar } from 'expo-status-bar';
import { useState } from 'react';
import { Alert, Button, StyleSheet, Text, TextInput, View } from 'react-native';
import {
  buildGuessMessage,
  compareGuess,
  createSecretNumber,
  parseGuess,
} from './src/number-guessing';
```

После импортов объявить `export default function App() { ... }` и поместить
следующие строки в начало тела компонента:

```js
const [secretNumber, setSecretNumber] = useState(() => createSecretNumber(Math.random()));
const [guessInput, setGuessInput] = useState('');
const [message, setMessage] = useState('Guess a number between 1-100');
const [attemptCount, setAttemptCount] = useState(0);
const [errorMessage, setErrorMessage] = useState('');
```

Нельзя вычислять секрет обычной строкой в теле `App`, иначе выражение выполнится при каждом рендере. Ленивый инициализатор state решает эту проблему для начала первого раунда.

### Шаг 6. Связать управляемое поле

```jsx
<TextInput
  accessibilityLabel="Guess input"
  keyboardType="numeric"
  onChangeText={setGuessInput}
  placeholder="Enter a number from 1 to 100"
  placeholderTextColor="#64748b"
  style={styles.input}
  value={guessInput}
/>
```

Проверка: ввод изменяет `guessInput`, а программный `setGuessInput('')` очищает поле.

### Шаг 7. Реализовать обработчик в правильном порядке

```js
function handleGuess() {
  const parsed = parseGuess(guessInput);
  if (!parsed.ok) {
    setErrorMessage(parsed.error);
    return;
  }

  const nextCount = attemptCount + 1;
  const status = compareGuess(secretNumber, parsed.value);
  setAttemptCount(nextCount);
  setErrorMessage('');

  if (status === 'correct') {
    Alert.alert('Correct!', `You guessed the number in ${nextCount} guesses`, [
      { text: 'OK', onPress: startNewRound },
    ]);
    return;
  }

  setMessage(buildGuessMessage(status, parsed.value));
}
```

Ключевой порядок: валидация раньше счётчика; `nextCount` раньше `Alert`; ветка `correct` раньше построения обычной подсказки.

### Шаг 8. Реализовать сброс раунда

```js
function startNewRound() {
  setSecretNumber(createSecretNumber(Math.random()));
  setGuessInput('');
  setMessage('Guess a number between 1-100');
  setAttemptCount(0);
  setErrorMessage('');
}
```

Передавать нужно `onPress: startNewRound`, без скобок вызова.

### Шаг 9. Добавить наблюдаемость и доступность

Динамическим текстам назначаются точные `testID`: `hint-message`,
`attempt-count`, `error-message`. Для подсказки, счётчика и ошибки используется
`accessibilityLiveRegion="polite"` — это Android-prop для TalkBack; поведение
VoiceOver на iOS нужно проверять отдельно. У поля есть
`accessibilityLabel="Guess input"`, а кнопка имеет видимое имя `MAKE GUESS`.

### Шаг 10. Подтвердить полный цикл

Unit-тесты проверяют чистые функции. UI-тест подменяет `Math.random` и `Alert.alert`, затем воспроизводит ошибку, `low`, `high`, `correct`, `OK` и второй раунд. После этого выполняется ручная приёмка на устройстве.

## 8. Разбор текущего кода

### `App`

`App` — функциональный компонент и координатор. Он получает пользовательские события, вызывает предметные функции и отображает state. Сам компонент не принимает props и экспортируется по умолчанию.

### Ленивый `secretNumber`

`useState(() => createSecretNumber(Math.random()))` принимает функцию-инициализатор. Она создаёт первый секрет при монтировании компонента. Обычные обновления `guessInput`, `message` и других state не создают новый секрет.

### `guessInput`

Значение остаётся строкой. Это позволяет отличить пустой ввод и необычные форматы до преобразования. Пара `value` и `onChangeText` делает `TextInput` управляемым.

### `startNewRound`

Функция задаёт согласованное состояние нового раунда пятью setter-вызовами. Она создаёт новый секрет, очищает поле и ошибку, возвращает начальную подсказку и обнуляет счётчик.

### `handleGuess`

Это единственная точка обработки кнопки `MAKE GUESS`. Ошибочная ветка меняет только `errorMessage`. Успешная ветка увеличивает попытки и очищает старую ошибку. Статусы `low/high` меняют `message`; `correct` вызывает `Alert`.

### Почему используется `nextCount`

Вызов `setAttemptCount` планирует обновление, но текущее замыкание обработчика всё ещё содержит старый `attemptCount`. Локальная переменная `nextCount` равна новому значению и поэтому даёт верный текст `You guessed the number in 3 guesses`.

### `Alert` и callback

Новый раунд не начинается сразу после совпадения. Пользователь успевает прочитать результат, а `startNewRound` вызывается нативной кнопкой `OK`.

### Чистый модуль

Функции из `src/number-guessing.js` не обращаются к state, UI, времени или сети. Даже случайность передаётся в `createSecretNumber` параметром. Поэтому границы можно проверить фиксированными числами.

### Тестовая стратегия

Unit-тесты быстро покрывают правила. UI-тест проверяет соединение частей и намеренно подменяет внешнюю недетерминированность: `Math.random` и `Alert.alert`. Assertions используют видимые роли, `accessibilityLabel` и `testID`.

## 9. Управляемая практика

### Упражнение 1. Таблица `parseGuess`

Ученица заполняет результат до запуска тестов.

| Ввод | Результат |
|---|---|
| `' 75 '` | `{ ok: true, value: 75 }` |
| `'075'` | `{ ok: true, value: 75 }` |
| `'100'` | `{ ok: true, value: 100 }` |
| `'0'` | Ошибка диапазона |
| `'1.0'` | Ошибка формы записи |
| `'1e2'` | Ошибка формы записи |
| `''` | Ошибка формы записи |

Модельная реплика ученицы: «`trim` разрешает внешние пробелы, regex разрешает только цифры, затем диапазон разрешает 1–100».

### Упражнение 2. Трассировка state

Начало: секрет 75, `attemptCount = 0`, ошибка пустая.

1. Ввод `0x10`: появляется точная ошибка, count 0.
2. Ввод `50`: ошибка очищена, `message = 'Your guess 50 is too low'`, count 1.
3. Ввод `90`: `message = 'Your guess 90 is too high'`, count 2.
4. Ввод `75`: `Alert` сообщает 3 попытки.
5. Нажатие `OK`: новый секрет, пустое поле, начальная подсказка, count 0, пустая ошибка.

### Упражнение 3. Найти ошибочную строку

Преподаватель показывает варианты:

```js
onPress: startNewRound
onPress: startNewRound()
```

Ученица выбирает первый и объясняет: «Первый передаёт callback, второй немедленно вызывает функцию и передаёт её результат».

### Упражнение 4. Дописать assertion устно

После ошибочного ввода ожидается:

```js
expect(ui.getByTestId('attempt-count')).toHaveTextContent('Attempts: 0');
```

После первого допустимого низкого ввода:

```js
expect(ui.getByTestId('hint-message')).toHaveTextContent('Your guess 50 is too low');
```

## 10. Самостоятельная практика

## 11. Диагностика ошибок

| Симптом | Вероятная причина | Проверка | Исправление/объяснение |
|---|---|---|---|
| Иногда секрет равен 0 | Нет `+ 1` | Подставить `randomValue = 0` | Использовать `Math.floor(randomValue * 100) + 1` |
| Никогда не получается 100 | Неверный множитель или граница | Подставить `0.999999` | Ожидать 100 для текущей формулы |
| Пустая строка проходит как число | Сразу вызван `Number(text)` | Проверить `Number('')` | Сначала `trim` и regex |
| `1e2` принимается как 100 | Нет проверки формы записи | Ввести `1e2` | Проверять `/^\d+$/` до `Number` |
| Ошибка увеличивает count | Setter расположен до проверки | Проследить ветку `!parsed.ok` | Оставить ранний `return` до `nextCount` |
| Подсказки перепутаны | Сравнивают аргументы в обратном порядке | Секрет 75, догадка 50 | `guess < secret` означает `low` |
| Alert показывает на одну попытку меньше | Используется старый `attemptCount` | Правильная первая догадка должна дать 1 | Использовать `nextCount` |
| Раунд сбрасывается до чтения Alert | Написано `onPress: startNewRound()` | Поставить лог или посмотреть state | Передать `onPress: startNewRound` |
| Поле не очищается после `OK` | Поле неуправляемое либо нет setter | Проверить `value={guessInput}` | Сохранить пару `value`/`onChangeText` и сброс `setGuessInput('')` |
| Секрет меняется при вводе | Генерация выполняется в теле компонента | Посчитать вызовы `Math.random` | Использовать ленивый initializer и менять секрет только в `startNewRound` |
| Тест Alert зависает/открывает нативное окно | `Alert.alert` не замокан | Посмотреть `jest.spyOn(Alert, 'alert')` | В UI-тесте подменить API и вручную вызвать callback |
| Metro показывает старое состояние bundle | Устарел кеш | Перезапустить после остановки | `npx expo start --clear` |
| Android не открывается по `a` | Эмулятор не запущен или не виден | Дождаться загрузки устройства | Запустить AVD/устройство и повторить `a` |
| iOS не открывается по `i` | Нет доступного Simulator или среда не macOS | Открыть Simulator | iOS Simulator запускается только на macOS с Xcode |

Правило диагностики: сначала воспроизвести симптом одним минимальным входом, затем назвать ожидаемый state, найти первую строку расхождения и только после этого менять код.

## 12. Вопросы преподавателя и полные ответы

1. **Почему секрет создаётся через функцию внутри `useState`?**  
   React использует её как ленивый инициализатор. Первый секрет вычисляется при создании state, а не при каждом повторном рендере, вызванном вводом или изменением сообщения.

2. **Как формула получает диапазон 1–100?**  
   `Math.random()` возвращает значение от 0 включительно до 1 не включительно. После умножения на 100 получается `[0, 100)`, после `Math.floor` — целые 0–99, после `+ 1` — целые 1–100.

3. **Почему `TextInput` хранится строкой?**  
   Нативное поле передаёт текст. Пока значение остаётся строкой, можно различить пустой ввод, пробелы, дробь, знак, экспоненциальную и шестнадцатеричную запись до числового преобразования.

4. **Почему недостаточно `keyboardType="numeric"`?**  
   Это подсказка платформе о раскладке клавиатуры, а не правило данных. Значение может поступить вставкой, с аппаратной клавиатуры или в платформенно-зависимом формате, поэтому нужна программная валидация.

5. **Что именно разрешает `/^\d+$/`?**  
   `^` и `$` требуют совпадения всей строки, `\d` означает десятичную цифру, `+` — одну или более цифр. После `trim` разрешены `1`, `075`, `100`, но не пустая строка, знак, точка, запятая, буква, `e` или `x`.

6. **Почему `'075'` допустимо?**  
   Строка состоит только из цифр и после преобразования равна 75, что входит в диапазон. Это поведение явно закреплено unit-тестом.

7. **Зачем `parseGuess` возвращает объект, а не только число?**  
   Дискриминирующее поле `ok` явно отделяет успех от ошибки. При успехе доступно `value`, при ошибке — готовое `error`; не нужно использовать неоднозначные значения вроде `0` или `null`.

8. **Почему неверный ввод не считается попыткой?**  
   В ветке `!parsed.ok` устанавливается ошибка и выполняется `return`. Код вычисления `nextCount` находится ниже и не исполняется.

9. **Что означают `low` и `high`?**  
   Они описывают догадку относительно секрета. `low`: догадка меньше секрета; `high`: догадка больше секрета.

10. **Почему нужен `nextCount`?**  
    Setter state не меняет значение переменной текущего рендера синхронно. `nextCount` локально содержит старый count плюс один и позволяет сразу вывести точный итог, включая текущую правильную попытку.

11. **Почему после правильного ответа не меняется `message`?**  
    Ветка `correct` показывает отдельный `Alert` и завершается `return`. Обычная подсказка строится только для `low/high`. После `OK` `message` сбрасывается к начальной строке.

12. **Почему `startNewRound` передаётся без круглых скобок?**  
    `onPress` ожидает функцию, которую вызовет позже. Круглые скобки вызвали бы сброс сразу при построении конфигурации `Alert`.

13. **Что делает controlled `TextInput`?**  
    `value={guessInput}` задаёт отображаемое значение из React state, а `onChangeText={setGuessInput}` записывает пользовательское изменение обратно. State становится единым источником истины.

14. **Почему чистые функции тестировать проще?**  
    Их результат зависит только от аргументов; они не рендерят UI и не меняют внешнее состояние. Можно передать фиксированный вход и точно сравнить выход.

15. **Зачем подменять `Math.random` в UI-тесте?**  
    Случайный секрет сделал бы сценарий неповторяемым. Фиксированные `0.74` и `0.24` гарантируют секреты 75 и 25 и позволяют проверить обе подсказки и два раунда.

16. **Зачем подменять `Alert.alert`?**  
    Тест получает вызов и конфигурацию нативного API без реального диалога. Затем он извлекает `onPress` кнопки `OK` и вызывает callback внутри `act`.

17. **Что хранится после полного перезапуска?**  
    Ничего. Все пять значений находятся только в React state, постоянное хранилище не используется, поэтому начнётся свежий раунд.

18. **Чем `testID` отличается от `accessibilityLabel`?**  
    `testID` даёт стабильный технический селектор тесту. `accessibilityLabel`
    сообщает пользователю назначение элемента через assistive technologies. В
    текущем коде поле имеет label, а динамические тексты идентифицируются
    `testID`. На Android TalkBack может объявлять их через live region; для iOS
    VoiceOver проводится отдельная ручная проверка.
